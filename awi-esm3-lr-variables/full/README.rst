Full-catalog LR conversion and retesting
=======================================

This opt-in extension inventories the full LR CMIP7 rule catalog, raw-monthly
fallbacks, REcoM and atmospheric CO2 additions, and explicitly unmapped requests.
This is the single operational LR workflow, including REcoM and atmospheric
CO2. The parent profile and raw YAML files provide shared fallback mappings;
the retired standalone raw-monthly controller and its site configuration
have been removed.

Unmapped requests are not all recoverable from existing output. The inventory
includes conditional DReq products, processes absent from some model builds,
and diagnostics that must be enabled before a simulation. A rule cannot
reconstruct a field that was never saved. Every unresolved request remains
visible in the coverage report; unsupported fields are never replaced by zero
or by a different tracer.

Only reusable source, tests and configuration examples belong in Git. Actual
configuration, environments, metadata/CV caches, mesh and forcing files, model
data, generated recipes, test results and PDFs belong outside this checkout.
No official CMIP tables are generated by this extension.

For a fresh full conversion with mandatory validation, run
``full/scripts/start_verified_leg.py EXPERIMENT --leg YYYYMMDD-YYYYMMDD
--config /outside/repo/config.json`` using the configured Python inside a
Slurm allocation. Depend on the exact leg's successful LPJ-GUESS merge job
when postprocessing is pending. This performs a fresh source audit, freezes
the plan and tests every READY product for one representative year. The
gate releases remaining product-years only when all those tests pass.
Each leg gets separate audit, configuration, validation and result records.

Install a reviewed checkout
--------------------------

Clone the repository, select the reviewed branch or commit, and run from
``awi-esm3-lr-variables``::

    bash full/scripts/setup-environment.sh \
      --venv /outside/repo/cmor-venv --python /path/to/python3

The installer refuses to overwrite an existing environment or put one inside
the checkout. It installs this repository in editable mode plus the pinned
dependencies in ``full/requirements-extra.txt`` and runs ``pip check``. It does
not run ``git pull``, initialize external metadata caches, alter model output,
or submit jobs. Python 3.10 is the recorded baseline; the pinned extras require
at least Python 3.10. Native NetCDF/HDF5, UDUNITS and other scientific-library
requirements must be available for the chosen platform.

The extras include CF units, the CF/WCRP compliance checkers, ESGVOC,
``cmip7_repack``, the data-request API, ``pyfesom2``, ``tripyview``, SciPy and
Matplotlib. They are direct-dependency pins, not a transitive lock guaranteed
for every Python/OS combination. Plans retain ``pip freeze`` in their
``reproduce`` directory. Preserve that record with the selected Git commit
when reproducing a tested environment; installation alone is not validation.

An optional, sanitized Python 3.10 dependency snapshot is included. To replay
it on a compatible platform, add this installer argument::

    --lock full/config/requirements-tested-py310.lock

This installs the snapshot before installing the checkout with ``--no-deps``.
The recorded versions may fail to install on a different Python/platform;
the lock contains neither private paths nor wheel hashes and does not pin
system libraries. Do not silently relax it when claiming an exact replay.

Configure paths outside Git
---------------------------

Copy ``full/config/example.json`` outside the checkout and
review every placeholder. The repository is inferred from this checkout;
use the installed Python through ``PYCMOR_PYTHON`` or an activated environment
(an optional ``python`` setting can pin it). Configure the
results root, authoritative DReq metadata, CMIP CV directory, initialized
ESGVOC cache, CORE3 mesh and greenhouse-gas forcing, plus site-specific Slurm
resources. Provide reviewed experiment metadata rather than treating spinup
metadata as a publication template. The current scientific routes are for
TCO95/CORE3; a different grid needs scientific review.

Optional auxiliary inputs and comparison baseline:

* ``model_level_table``: the correct OpenIFS coefficient table for the actual
  model levels (L91 for this LR configuration, not the HR L137 table).
* ``basin_mask_file``: a validated CORE3 basin mask. A missing mask blocks
  only products requiring it; it must not be replaced with an HR/DARS2 mask.
  Node coordinates/order must match the mesh. Ocean diagnostics decode
  ``flag_values`` through ``flag_meanings``; numeric IDs alone do not define
  an ocean. Both Arctic/Southern encodings are supported without changing
  the mask. Missing/ambiguous labels or unclassified nodes are errors.
* ``hr_reference_manifest``: an optional text file containing relative DRS7
  NetCDF filenames from an HR archive. All referenced products are added to
  the requested scope, and ``report/hr_reference_coverage.csv`` and
  ``hr_reference_summary.json`` explicitly distinguish planned coverage from
  successful completion of every required task. Years, grids and duplicate
  versions are not counted as additional scientific products.
* ``decadal_window``: optionally ``[2600, 2609]`` or another exact ten-year
  window ending no later than the selected completed leg. By default the
  window is the ten years ending with that leg. Earlier archived input is
  allowed only after full-window coverage checks; exact primary and
  secondary/vector-partner dependencies are frozen into the plan.

Carbon routes are blocked until their model conventions are reviewed. Read
``rules/recom.yaml`` and ``rules/co2.yaml`` before selecting
``"carbon_profile": "awiesm3-v3.5.1-cc-raw-v1"`` in JSON. Atmospheric CO2 flux
routes additionally require ``carbon_context.external_emissions_reader`` to
be explicitly ``false``: they do not account for extra external-reader
emission terms. Do not set this flag merely to make a blocked rule run.

``carbon_context.co2_representation`` must distinguish
``nonuniform_diagnostic_tracer`` from ``prescribed_uniform``. The former
does not use the HR prescribed-concentration ``co2mass`` recipe: the CMIP7
processing note requests mole fraction instead for nonuniform CO2. The
tracer mole-fraction and validated flux products remain in scope. Unknown
CO2 representation stays blocked rather than silently substituting the
prescribed 284 ppm for a diagnostic tracer.

Native daily REcoM streams
-------------------------

The audited rules now also read actual daily means for ``intpp``, surface
``chl``, ``o2``, ``co3``, ``ph``, ``phyc`` and ``phydiat``, and three-dimensional
``detoc``, ``dissoc``, ``zmeso``, ``zmicro`` and ``zooc``. These are separate
frequency/vertical-shape products, not necessarily new variable short names.
Daily data are never fabricated by repeating monthly means. Input checks
require complete ordered calendar days, including leap days, daily-mean
metadata, and the reviewed source units. Three-dimensional files are read
lazily in one-day chunks. The independent value audit matches actual dates,
including a leap-day sample when present.

Two additional monthly Southern Ocean diagnostics, ``intpbn`` and ``intpbfe``,
use the reviewed net nitrogen-production diagnostics ``NNAn + NNAd``.
Their rules require the actual leg's REcoM namelist: coccolithophores must be
disabled and the reviewed nitrogen-loss parameters must agree. Iron production
uses that namelist's ``fe2n`` value with its micromol-Fe/mmol-N units, not an
assumed universal ratio. The namelist is frozen as an input dependency; missing
or incompatible settings block these recipes. Only the requested south-of-30S
native cells are retained, and value checks match their original coordinates.

The monthly ``ficeberg`` surface alternative uses the signed sum of the four
native iceberg freshwater terms multiplied by freshwater density. Only
verified ice-shelf cavity nodes, where this FESOM implementation excludes
iceberg injection, are set to zero; missing exposed-ocean data fail validation.
The independent audit checks every native cell for the first and last months.
No three-dimensional iceberg profile or subdaily flux is invented.

Where the pinned DReq explicitly says to omit a regional duplicate if the
exact global equivalent is produced, ``report/products.csv`` identifies that
global product and its status. This is not counted as another converted file
or a separate regional PASS. Frequency, vertical shape, units and physical
definition must match; a monthly/global field cannot stand in for a daily
or depth-resolved request.
Conversely, requested monthly Southern Ocean surface products without an
official global-surface counterpart are generated from the reviewed monthly
three-dimensional tracer: select the first native layer, then retain native
cells south of 30S. The validator locates their original cells by coordinates,
not by assuming regional and global array indices are interchangeable.

Decadal diagnostics
-------------------

Decadal products require 120 actual monthly records with validated month
bounds. Restart snapshots and static geometry cannot replace missing monthly
``hnode`` or ``volo`` histories. For example, if those histories first exist
in 2605--2609, the earliest complete window is 2605--2614 after the following
leg finishes. Rerunning the normal command with ``--leg latest`` then discovers
and validates that window automatically; no relaxed five-year-as-decade mode
exists. This does not require changing the model or rewriting old output.

Instantaneous output has a different time-axis rule: a DReq ``time-point``
product may correctly omit time bounds. It still must contain every required
timestamp, with no duplicates or reversals. Time-interval products continue
to require bounds.

For a production checkout, leave ``allow_dirty`` false. An optional ``commit``
pins a specific revision; omitting it uses the checked-out HEAD. A deliberately
uncommitted development checkout may use ``allow_dirty: true`` in its external
configuration. Source fingerprints still guard the frozen plan: changing code
after planning does not silently update an existing campaign. Use a fresh
results root for changed code/configuration. Do not commit private site paths
or enable dirty mode merely to bypass a provenance mismatch.

Check and run one leg
--------------------

Use an experiment root, not ``outdata`` or an active ``run_...`` directory::

    export PYCMOR_PYTHON=/outside/repo/cmor-venv/bin/python
    ./full/cmorize --config /outside/repo/config.json \
      /absolute/path/to/experiment --leg latest --check

``--check`` prepares the complete inventory and writes reports under the
external results root. It does not convert products or submit jobs, but is
not a filesystem-read-only operation. Missing input streams, unresolved
mappings and insufficient time windows are reported, never invented.

After reviewing the inventory, omit ``--check`` to submit the Slurm planning,
conversion and reporting workflow::

    ./full/cmorize --config /outside/repo/config.json \
      /absolute/path/to/experiment --leg YYYY0101-YYYY1231

Replace the leg placeholder with actual start/end years. ``--leg latest``
selects the latest verified completed compute leg and requires its successful
postprocessing; it does not silently fall back if that leg is incomplete.
Explicit-leg runs perform the same completion checks. Slurm accounting must
remain available. A submitted job ID is not evidence of completed conversion.
For synchronous execution within an allocated postprocessing job, use
``--run``; do not run production conversions on a login node.

A future model-side hook can pass an exact leg and
``--dependency afterok:MERGE_JOB_ID``. Installing this extension does not
install a hook, change model output switches, or modify queued model jobs.
Verify generated model namelists/XML, not only source YAML: an already-prepared
leg may still use older output settings.

Results and known limits
------------------------

Each external campaign directory has this layout::

    <results>/<experiment>__<path-hash>/<leg>/
      NOT_FOR_PUBLICATION/       products by product/year/attempt
      recipes/                   generated rules
      coverage.json              full inventory including blocked requests
      report/products.csv        status/reason for every product-year
      report/variable_inventory.csv
      report/summary.json        overall status and count definitions
      reproduce/                 exact settings/code/dependency evidence
      logs/                      scheduler logs
      submission.json            submitted job IDs

Annual tasks, fixed fields, decadal tasks, distinct compounds, variable names and output files are
different counts. The earlier full-catalog audit contained 206 unmapped
requests; that is a recorded limitation, not a promise that the remaining
requests will pass on another dataset. Consult the fresh inventory for exact
counts. Daily/subdaily output cannot be recovered from monthly means. A
five-year leg alone cannot supply a decadal product, but the planner may use
the previous five years of verified archived input in its explicit ten-year
window. Missing years remain blocked; static ocean geometry is not a
replacement for time-varying thickness/volume. Additional REcoM diagnostics
may require a newer model build and enabled output.

Derived daily land inputs are checked per physical variable stream; different
variables recorded at the same time are not duplicate time chunks. Daily
storage changes require the previous December 31 daily state. If that
boundary is unavailable the affected year is blocked, not filled with zero.
This applies to canopy and snow changes as well as total/soil water changes.
``dgw`` requires groundwater storage. The former ``swvl4`` mapping represented
deep soil moisture and was removed; the request remains explicitly blocked
until a genuine groundwater diagnostic is available.
Daily vertically integrated ``hfx``/``hfy`` use a bounded one-day calculation
with spatial blocks and one cached month of native layer thickness. This
preserves the existing transport formula and geometry while avoiding an
annual graph of shared three-dimensional triangle-node gathers.
The existing ``mrsow`` formula retains the HR recipe's uniform-porosity
approximation; matching HR coverage does not establish an independent
scientific validation of that approximation.

``BLOCKED`` and ``FAILED`` are not success. ``PASS`` means the stated
conversion/data checks passed, not publication approval or an independent
scientific audit of every value. Formal CF/WCRP findings are retained
separately. A full-output end-to-end test is still data-dependent; this
extension does not claim that all 500 catalog products pass. Never delete
raw model data or publish test products based only on the overall report.

Developer and operational checks
-------------------------------

Run the isolated regression suite without scheduler submission::

    PYCMOR_PYTHON=/outside/repo/cmor-venv/bin/python bash full/tests/run-tests
    bash -n full/scripts/setup-environment.sh
    ./full/cmorize --help
    /outside/repo/cmor-venv/bin/python full/scripts/retest_all_products.py --help

The representative retest utility selects one READY year for every distinct
compound in a newly frozen plan and retains blocked requests in its report.
Preparation/reporting and worker execution are separate; inspect its help
before running workers in an allocation. This bounded test is not a complete
all-years publication campaign.

After ``prepare``, use ``submit CAMPAIGN --compounds COMPOUND ...
--full-after-pass`` to run a targeted validation array and submit all planned
product-years only after every selected conversion and basic-data check passes.
Omit ``--compounds`` to validate every READY product first. Missing, failed or
changed test outputs block the gate. ``representative_test/gate_result.json``
records the decision; it does not certify publication readiness. The normal
full launcher does not implicitly enable this optional regression gate.

The full driver sets ``PYCMOR_WORKER_COMPUTE=off`` to write large outputs
chunk-by-chunk with the synchronous writer, rather than gathering an entire
year of three-dimensional data into a Dask worker. Outside this driver,
pycmor's automatic worker path limits eager materialization to 1 GiB per
batch; ``PYCMOR_WORKER_COMPUTE_MAX_BYTES`` controls that threshold. These
settings change memory use, not numerical values. Decadal reductions preserve
depth-coordinate attributes, and full-campaign success checks now reject
missing ocean depth metadata and mismatched DReq units/standard names.

Generate an optional operational PDF outside Git::

    /outside/repo/cmor-venv/bin/python full/scripts/make_cmorization_guide.py \
      --config /outside/repo/config.json --output /outside/repo/guide.pdf

The guide reads the supplied configuration and documents generic commands;
it does not select a leg, inspect model output, submit jobs or create tables.

Review only the intended reusable files before committing::

    git diff -- awi-esm3-lr-variables/README.rst awi-esm3-lr-variables/full
    git status --short

Review the full LR workflow and its shared engine/helper changes together.
Keep environments, private site configuration, generated data, caches, logs
and PDFs outside Git. The working tree is intentionally unstaged during
development; staging and committing are separate reviewed actions.

November 2026 supervisor review
-------------------------------

The full workflow requires lazy writes, including the ``trigger_compute`` step
before the writer. ``lazy_write: true`` is applied to generated recipes. The CLI
must respect ``enable_dask: false``; creating ``Client(None)`` starts an unintended
cluster. Neither a larger memory request nor an omitted product is a memory fix.

Global surface ``tos``/``sos`` means use upstream ``global_mean`` on the
native SST/SSS fields, with top-level ``nod_area`` from CORE3 diagnostic geometry
and the actual finite surface footprint. Volume means ``thetaoga``/``soga``
are different quantities. The new means have an independent all-surface-node comparison for
every month. Raw routes use declared grid labels and native land fields expand
to the full atmosphere grid. Global native cell counts are checked on output.

Use DReq v1.2.2.5 exported with API 1.4 when reproducing the reviewed metadata:
SHA256 ``eccf9f9296488581939310a37c60849501f77c9c9dd27faf8585b2345c18b9e3``.
Exporter versions can change the exported file; record the exporter as well as
the DReq version. Recompute coverage after a metadata change. Removed compounds
remain explicitly blocked, and cannot be used as a validation-gate selection.

For CF, WCRP and AICC configure ``qc_tests``, ``cmip7_tables_path`` and
``aicc_grid_config``. Pin the tables checkout. Missing requested checker reports
fail conversion validation. Findings are retained separately and do not constitute
publication approval. The current development spinup uses an explicit test
identity; a v3.5.1 run must not be relabelled as registered v3.5.2 without review.

``supervisor_audit.py`` records static/configuration evidence and optionally
runs bounded scientific source checks under Slurm. Its REVIEW_REQUIRED records
are unresolved work, not passes. Approximate HR climatologies do not establish
scientific validity for an LR spinup. XIOS operation/cadence, vector build/frame,
pressure subsets, carbon pathways and all output/QC findings need actual evidence.

``build-native-io.sh`` builds netCDF-C and Python I/O wheels against a supplied
thread-safe HDF5 prefix. It never installs the wheels. Install only after checking
that no conversion workers use the environment. Record linked shared libraries,
compiler/build options, source checksums and the updated dependency lock. Do not
copy Levante library paths or settings to another HPC.

Full-window climatology recipes freeze every source year and calculate
``mean within years`` followed by equal-weight ``mean over years``. Only the
closing task writes the selected window. They do not use the legacy mutable
accumulator or its Levante default path. Missing years/months are errors.

The report separates realm product counts, short-name counts, task states and
validated physical NetCDF files. A fully blocked request remains in scope.
